## 一、编码说明（务必先看）

本文件采用「跨平台中文不乱码」方案：

1. 源文件以 UTF-8 无 BOM 保存
2. 所有中文输出字符串均使用 `u8""` 前缀（强制以 UTF-8 字节存入 exe）
3. Windows 下运行时自动 `SetConsoleOutputCP(CP_UTF8)` 将控制台切到 UTF-8
4. Windows 下的中文文件名走宽字符 API（UTF-16），不再按 GBK 误判
5. Linux / macOS 终端默认 UTF-8，无需额外设置

只要「原样」保存、用正常方式编译，中文就不会乱码。

## 二、各 IDE 打开方式（任选其一）

### [1] Dev-C++（Windows，教室常见）

- 直接打开 `programming.cpp` 即可
- 若中文显示成方块/问号：菜单「文件 → 另存为」，编码选 UTF-8 再覆盖保存
- 按 F9 编译并运行

### [2] Visual Studio（Windows）

- 新建「控制台应用」空项目，把 `programming.cpp` 加入工程
- 直接按 F5 运行（VS 默认即按 UTF-8 处理，无需设置）

### [3] VS Code（Windows / Linux / macOS）

- 用 VS Code 打开所在文件夹
- 安装 C/C++ 扩展，点「运行 → 运行 C++ 文件」
- 或直接用下方命令行编译

### [4] 命令行 / 终端（推荐，最通用）

**Linux / macOS：**

```bash
g++ programming.cpp -o programming
./programming
```

**Windows（MinGW / MSYS2）：**

```bash
g++ programming.cpp -o programming.exe
.\programming.exe
```

## 三、编译命令参考

如需显式指定编码（一般不用，已用 `u8""` 锁定），可加：

```bash
g++ programming.cpp -o programming \
    -finput-charset=UTF-8 -fexec-charset=UTF-8
```

如果对方使用 C++20 严格模式（如 `-std=c++20`）编译报错：

- **方案 A**：改用 C++17 编译 → `-std=c++17`
- **方案 B**：保留 C++20，把 `cout << u8"..."` 强转 → `cout << (const char*)u8"..."`

> 本程序只用标准 C++11 语法（含自实现的 streambuf），不依赖 `fstream::open(wchar_t*)` 这类编译器扩展，g++ / Clang / MSVC / MinGW 均可编。

## 四、运行步骤（按顺序四步）

**第 1 步：数据文件名**

- 直接回车 → 使用默认 `programming.txt`
- 或输入自定义名字：不带 `.txt` 会自动补上（输入“成绩单” → `成绩单.txt`）
- 首尾空格会自动去掉，中文名也可以（Windows 下走宽字符 API，不会乱码）
- 屏幕会打印该文件的绝对路径，复制即可在资源管理器中定位 / 导入

**第 2 步：排序方向**

- `1` = 降序：数值越大排名越靠前（成绩、得分等“越大越好”）——直接回车即默认此项
- `2` = 升序：数值越小排名越靠前（耗时、扣分、故障数等“越小越好”）
- 方向只作为“排名口径”，不写进数据文件，旧文件照常可读
- 管理员之后还能用菜单「4. 切换排序方向」随时改
- 选升序时会提示：第 1 档对应数值最小的一批，避免看反

**第 3 步：身份**

- `1` = 管理员（老师等）：新建 / 读取 / 补充写入 / 切换排序方向
- `2` = 一般用户（家长等）：按姓名（或编号）查排名、超越比例、档位

**第 4 步**：按菜单操作（详见下节）

## 五、管理员菜单（身份选 1）

输入操作类型：

1. 新建
2. 读取
3. 补充写入
4. 切换排序方向

> 菜单上方会实时显示当前排序方向。

**[1] 新建**

- 输入人数（或参数总数）→ 输入数据种类数量 → 逐条录入
- 录入格式：`姓名（或编号） 数据1 数据2 ……`（每行一条）
- 随即自动排序并保存；屏幕同时打印结果

**[2] 读取**

- 只读显示当前文件内容（按当前排序方向），不改动任何文件
- 文件为空时提示“未查到数据”
- 文件残缺时会先给出警告，再显示已成功读到的部分

**[3] 补充写入**

- 沿用原文件的数据种类数量，只追加若干条新记录
- 新旧数据合并后全局重排序，再整体写回
- 保存前自动把上一版备份为 `programming.txt.bak`
- 原文件不存在 / 无有效数据 / 文件残缺时拒绝追加，并提示“原文件未被改动”

**[4] 切换排序方向**

- 在升序与降序之间来回切换，切完立刻按新方向重排显示一遍
- 数据文件内容一行都不改，只是排名口径变了
- 切换后继续回到菜单，可接着做其他操作

## 六、一般用户查询（身份选 2）

- 输入姓名或编号即可查询；输入 `exit` 或 `退出` 结束查询
- 查不到不会退出程序，提示后回到输入处，可反复重输
- 每次输入都重新读一次文件，管理员中途追加的数据也能立刻查到
- 存在同名（同编号）记录时，会提示“存在 N 条同名记录”并全部列出，建议改用唯一编号查询

**输出内容依次为：**

查询成功 → 表头 → 该条各项数据与总计 → 超越比例（超过百分之多少的成员）→ 具体名次 `|排名/总人数|`（并列时会标注“并列 N 人”）→ 档位

**档位说明：**

- 仅在数据种类数 `kinds` 为 2~9 时给出（单科成绩谈“综合档位”没有意义）
- 统一按名次四等分：第 1 档 / 第 2 档 / 第 3 档 / 第 4 档，四档人数接近 1:1:1:1
- 措辞保持中性，不写“优/差”——因为排序方向可切换，带好坏色彩的词容易看反
- 总计溢出的记录统一显示【不予分档】，并说明名次不反映真实水平

## 七、数据文件格式（可手工编辑 / 外部导入）

**第一行**：人数 `n`  数据种类数 `kinds`
**其后每行**：序号  姓名（或编号）  数据1 数据2 …… 数据`kinds`  总计

**示例（4 人、2 个数据项）：**

```text
4 2
1 C 100 95 195
2 A 90 80 170
3 B 70 60 130
4 D 55 50 105
```

**注意：**

- 字段之间用空格分隔，一行就是一条记录
- 文件的“序号”只是占位，程序加载后会按当前方向重新排序，名次以排序后的下标为准（即使导入一份乱序文件，排名也是对的）
- 总计允许与各项之和不一致，程序会按各项重算并提示“文件中的总计为 X，按各项重算应为 Y，已按重算值处理”
- 字段数不对时（多写一个数 / 少写一个数）会当场报出第几行、应有几个、实际几个，并拒绝用错位数据覆盖原文件
- 支持含 BOM 的旧文件；本程序自己写出的是 UTF-8 无 BOM

## 八、安全与容错（本版重点）

1. **总计溢出保护**
   各项之和超出 `long long` 范围时，录入阶段当场提示并重输该条，绝不把错误值写进文件；已存在的溢出记录在读取与查询中标注 `[总计溢出，请检查该项数据]`，并在任何排序方向下都排在最末、彼此并列，不再分出虚假的先后名次。

2. **保存三步走**（写 `.tmp` → 原文件改名 `.bak` → `.tmp` 原子替换）
   任一环节失败都不会破坏原文件；上一版始终留在 `.bak` 中。临时文件删除前会先关闭句柄，Windows 下不会残留 `.tmp`。

3. **输入保护**
   身份、管理员选项输错会提示并让你重输（提示里写明“请输入 1、2、3 或 4”）；人数 / 数据种类数 / 补充人数 ≤ 0 时取消本次操作并说明“原文件未被改动”；按下 Ctrl+Z / Ctrl+D 触发 EOF 时优雅退出，不会死循环。

4. **退化场景**
   空文件、文件不存在、只有 1 条记录、只有 1 种数据、各条项数不一致都有明确提示；数据种类数超过 30 时表头自动压缩为 `|数据1|数据2|数据3|数据4|……|数据N|总计|`，不再刷屏。

5. **管理员口令（默认关闭）**
   源码顶部 `#define ADMIN_PASSWORD_ENABLE 0`，默认不启用；需要时把 `0` 改成 `1` 并修改 `ADMIN_PASSWORD` 字符串，其余代码不用动。部署在公共机房时建议开启。

## 九、常见问题（FAQ）

**Q1：运行时中文乱码？**
A：说明终端不是 UTF-8。Windows 可在运行前执行 `chcp 65001` 切换代码页；本程序已自动调用 `SetConsoleOutputCP(CP_UTF8)`，通常无需手动操作。

**Q2：Dev-C++ 里中文是方块 / 问号？**
A：这是编辑器字体问题，不是编码问题。把文件「另存为 UTF-8」即可；字体换成 Consolas / 宋体可正常显示中文标点（【】、———— 等）。

**Q3：Linux / macOS 需要特殊处理吗？**
A：不需要。终端默认就是 UTF-8，GCC / Clang 会忽略 BOM，直接 `g++` 编译运行即可。

**Q4：数据文件 programming.txt 放哪里？**
A：和 exe / 可执行文件同一目录，程序会自动读取 / 创建；启动时会把绝对路径打印出来，复制即可定位。

**Q5：C++20 下 `u8""` 编译报错？**
A：C++20 起 `u8""` 类型是 `const char8_t*`，`cout` 不能直接输出。解决：用 `-std=c++17` 编译，或加 `(const char*)` 强转。

**Q6：为什么排名和我文件里写的顺序不一样？**
A：这是正常的。文件里的“序号”只是行号，程序加载后会按总计 → 逐项 → 编号三级规则重新排序，排名以排序后的结果为准（同分时按编号字典序，保证公平）。

**Q7：为什么我查的人显示【第4档】而不是【差】？**
A：本版把“优/良/一般/差”改成了中性的“第 1~4 档”。因为排序方向可切换，“优”在升序下反而对应数值最小的一批，容易看反。

**Q8：为什么同一个名字查出好几条？**
A：存在同名（同编号）记录，程序会全部列出并提示改用唯一编号查询。

**Q9：误操作改坏了数据怎么办？**
A：每次补充写入前都会把上一版备份为 `programming.txt.bak`，把 `.bak` 改名回 `.txt`（或删掉后缀）即可恢复上一版。

**Q10：能不能改某一条数据？**
A：目前只能新建 / 追加。改错一条时，建议手工编辑 txt（改完程序会按各项重算总计并提示），或用「1. 新建」整份重录。

## 十、技术原理（简要）

- **BOM（EF BB BF）**：告诉编辑器「这是 UTF-8」，Windows IDE 识别用；Linux / macOS / GCC / Clang 会自动忽略，无副作用。
- **`u8""` 前缀**：C++11 起保证字符串字面量以 UTF-8 字节存入可执行文件，绕过老 MinGW 默认把窄字符串转成 GBK 的问题。
- **`SetConsoleOutputCP(CP_UTF8)`**：运行时把 Windows 控制台切到 UTF-8 代码页，让 UTF-8 字节能被正确渲染。
- **宽字符文件 API**：Windows 下把 UTF-8 路径转 UTF-16，走 `GetFullPathNameW` / `_wfopen` / `_wrename` / `_wremove`，中文文件名不再乱码。
- **自实现 streambuf**：底层 `FILE*`（Windows `_wfopen`、其他 `fopen`），对外包一层 `istream` / `ostream`，业务代码 `>>` `<<` 语法不用改，且全部只用标准 C++11。
- **`safe_add()`**：相加之前先判溢出（溢出本身是未定义行为，事后判断不出来），溢出则标记 `overflow`、总计置 0，绝不产出 -2。
- **逐行严格解析**：每行 `getline` 取出后在该行内解析，核对字段数是否恰好为 `kinds + 3`（序号 + 姓名 + `kinds` 项 + 总计），多一个少一个都当场报行号。

> 三者配合 = 源码层能做到的跨平台中文零乱码方案。
